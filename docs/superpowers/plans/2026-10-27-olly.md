# olly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build olly, a tiny root Rust daemon that detects runaway memory via PSI plus per-app growth and throttles, freezes or kills the offender within seconds. It also provides a CLI, a Unix-socket IPC, a user-level notification agent, an incident log, and suggest-only Claude diagnosis.

**Architecture:** There is one library crate, `olly`, with two binaries:
- `olly` is the daemon and the CLI, as subcommands.
- `olly-notify` is the user-level notification agent. It is a separate binary so that `mlockall` in the daemon doesn't lock the D-Bus stack into RAM.

The core is a pure rule engine (`Engine::step(samples) -> StepOutput`), tested with synthetic sequences. Thin I/O layers sit around it: `/proc` and cgroup readers, an actuator, the PSI trigger, IPC, and the incident store. The daemon main loop is single-threaded and wakes on the PSI trigger fd, an eventfd for IPC commands, or a timeout. Per-connection IPC threads talk to it over mpsc channels.

**Tech Stack:** Rust 1.95 (edition 2021). Daemon dependencies: `serde`, `serde_json`, `toml`, `libc`. Agent only: `notify-rust`. Dev: `tempfile`. No async runtime and no CLI-parsing crate.

**Spec:** `docs/superpowers/specs/2026-10-27-olly-design.md`

## Global Constraints

- The emergency path never does network or LLM calls, never spawns processes, and never blocks on notifications.
- Root system service: `OOMScoreAdjust=-1000`, `mlockall(MCL_CURRENT|MCL_FUTURE)`, a small `MemoryMin=`. Target is under 10 MB RSS and about 0% CPU while idle.
- systemd-oomd stays untouched.
- KDE Plasma desktop session only. Game Mode is out of scope.
- Claude is suggest-only and runs as the desktop user. It never acts, never edits the allowlist, and never changes config.
- IPC socket is `/run/olly/olly.sock`, newline-delimited JSON, with peer uid checked via `SO_PEERCRED` (only root and `desktop_uid`).
- IPC never exposes: kill an arbitrary pid, allowlist removal, or threshold changes.
- `pause` requires a duration, maximum 3600s by default. While paused, throttle and freeze are suspended, but emergency kills still happen.
- Files: `/etc/olly/config.toml`, `/var/lib/olly/incidents.jsonl`, `/var/lib/olly/allowlist.toml`, `/run/olly/active.json`.
- Dry-run is the default on first install (`dry_run = true` in the shipped config).
- Voice: "olly" is always lowercase. Clarity first. Tone scales with severity: no jokes at critical or emergency. Notification bodies are 1–2 sentences. Never blame the user, never be smug.
- Unit for memory in all internal types: **bytes as `u64`**. Time: **milliseconds as `u64`** from a monotonic clock, injected (engine never reads the clock).

## Review Focus

1. **olly restarts or crashes while an app is frozen or throttled.** The app must not stay frozen forever. On SIGTERM olly resumes and unthrottles everything. On startup it reads `/run/olly/active.json` and undoes anything left over. Tested in Task 6 (`active_state_roundtrip`, `recover_undoes_leftovers`) and Task 9 (shutdown).
2. **A process exits, or its pid is reused, between sampling and acting.** olly must never signal the wrong process. Every process target carries its start time (`/proc/<pid>/stat` field 22), and that is re-checked before signalling. A vanished target is logged and skipped. Tested in Task 6 (`signal_skips_reused_pid`).
3. **`/proc` or cgroup files are missing or malformed** (process vanished mid-read, no zram, no `memory.swap.current`). These count as zero or get skipped, never a panic. Tested in Task 2 (`missing_files_are_tolerated`).
4. **A misbehaving IPC client** (garbage JSON, a line over 64 KiB, disconnecting mid-stream, a subscriber that never reads). The daemon loop must stay unaffected. Subscriber queues are bounded and drop when full. Tested in Task 8 (`garbage_line_gets_error`, `oversized_line_closes_connection`, `slow_subscriber_does_not_block`).
5. **Invalid `config.toml`.** The daemon still starts, using defaults, and logs a loud error. A safety daemon must not refuse to run over a typo. Tested in Task 1 (`invalid_config_falls_back_to_defaults`).

### Task 3: Sampling with lineage grouping

**Files:**
- Create: `src/sample.rs`, `tests/fixtures/steam/` (synthetic tree)

**Interfaces:**
- Consumes: Task 2 readers, `Config.desktop_uid`.
- Produces:
  ```rust
  pub struct SystemSample { pub t_ms: u64, pub psi: Psi, pub mem: MemInfo, pub zram_used: u64 }
  #[derive(Clone, PartialEq, Eq, Hash, Debug, Serialize, Deserialize)]
  pub struct AppKey { pub cgroup: String, pub root_pid: Option<i32> } // root_pid None => whole cgroup
  #[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
  pub enum TargetKind { Cgroup, Processes { pids: Vec<(i32, u64)> } } // (pid, start_time)
  pub struct AppSample { pub key: AppKey, pub name: String, pub exe: Option<PathBuf>, pub kind: TargetKind, pub bytes: u64 /* RAM+swap */, pub names: Vec<String> /* comm of every member, for allowlist */ }
  pub struct Sampler { root: PathBuf, uid: u32 }
  impl Sampler {
      pub fn new(root: PathBuf, uid: u32) -> Self
      pub fn system(&self, t_ms: u64) -> Option<SystemSample>
      pub fn apps(&self) -> Vec<AppSample>          // full: all procs of desktop uid
      pub fn cgroup_totals(&self) -> Vec<(String, u64)> // slow loop: memory.current+memory.swap.current per leaf under app.slice and session.slice
  }
  ```
- **Lineage algorithm** (`apps`). Only consider processes with `uid == desktop_uid` whose cgroup lies under `/user.slice/user-<uid>.slice/user@<uid>.service/`. Group the processes by cgroup. Within one cgroup:
  1. A process **joins its in-cgroup parent's group** if (a) its `exe` equals the parent's `exe`, or (b) its own `rss+swap` is below 64 MiB. Otherwise it **starts a new group**, as does a process with no parent in the cgroup. Small helpers such as `sh` and `reaper` stay with their parent, while a big child with a different exe (the game under Steam) becomes its own group, and Firefox's content processes (same exe) stay with Firefox. The group's root is the process that started it.
  2. If the cgroup ends up with exactly one group, emit `AppKey{root_pid: None}`, `TargetKind::Cgroup`, and `bytes = memory.current + memory.swap.current`.
  3. Otherwise emit one `AppSample` per group: `AppKey{root_pid: Some(root)}`, `TargetKind::Processes` with every member's `(pid, start_time)`, and `bytes = Σ(rss + swap)`.

  `name` is the root's comm.

  Note for implementers: step 2 merges children with a *different* exe? No. Step 1 already joins same-exe chains, so step 2 needs no merging, and every distinct-exe process tree is its own group. The one exception is a process whose exe differs from its in-cgroup parent's but which is *not* the top memory user. Simplify: a process joins its parent's group when (a) its exe matches the parent's, or (b) its own `rss+swap` is below 64 MiB. Small helpers such as `sh` and `reaper` then stay with their parent, while a big child with a different exe (the game) becomes its own group. This rule replaces steps 1–2.

### Task 6: Rule engine

**Files:**
- Modify: `src/engine.rs`
- Create: `src/actuator.rs`

This is the heart of olly. The engine is pure: it gets samples and the time, and returns actions and events.

**Interfaces:**
- Consumes: `SystemSample`, `AppSample`, `AppKey`, `TargetKind` (Task 3), `History` and `Allowlist` (Task 4), voice (Task 5), `Config`.
- Produces:
  ```rust
  pub fn classify(s: &SystemSample, t: &Thresholds) -> Level
      // avail% = available*100/total. Highest level whose full-threshold OR avail-threshold is met.
      // Watch also if some_avg10 >= watch_some. Calm otherwise.
  #[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
  pub struct Target { pub id: u64, pub key: AppKey, pub name: String, pub kind: TargetKind, pub bytes: u64 }
  #[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
  pub enum Action {
      Throttle { target: Target, high: u64 },          // high = max(bytes*105/100, bytes + 128 MiB)
      Unthrottle { target: Target },
      Freeze { target: Target },
      Resume { target: Target },
      Kill { target: Target, reason: KillReason },
  }
  #[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
  pub enum Event {
      Level { level: Level },
      IncidentStart { id: u64, t_ms: u64 },
      IncidentEnd { id: u64, t_ms: u64 },
      Acted { action: Action, message: Message, dry_run: bool },
      Notice { message: Message, frozen_id: Option<u64> }, // reminders, all-clear, hunches; frozen_id => show Kill/Resume
  }
  pub struct StepOutput { pub actions: Vec<Action>, pub events: Vec<Event> }
  ```

     - **Emergency:** kill the top recently growing candidate (reason `Emergency`). If none is growing, kill the largest candidate by `bytes` (reason `LastResort`). This happens even while paused.
