# olly Tray Face Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Plasma 6 system tray widget that shows olly as a robot face whose mood follows olly's real state, with a click popup for status, incidents and quick actions.

**Architecture:**
- The daemon's `status` reply gains a few fields: swap, PSI some, the top app, frozen-app deadlines, and incident and action flags.
- The `olly` CLI gains `--json` output for `status` and `incidents`, with a 1 s offline timeout.
- A QML plasmoid (`org.olly.tray`) polls the CLI every 2 s and draws the face from SVGs.
- All decision and formatting logic lives in one pure JS library, tested with node.

**Tech Stack:** Rust (existing crate), QML / Plasma 6 (`org.kde.plasma.plasmoid`, `org.kde.plasma.components`, `org.kde.kirigami`, `org.kde.ksvg`, `org.kde.plasma.plasma5support`), node ≥ 20 for JS tests.

**Spec:** `docs/superpowers/specs/2026-10-27-olly-tray-design.md`. The look is defined by `docs/superpowers/specs/2026-10-27-olly-tray-mockup.html`. The base daemon spec is `docs/superpowers/specs/2026-10-27-olly-design.md`, and the wire format is `docs/ipc.md`.

## Global Constraints

- Never run `sudo`, root steps, `scripts/install.sh`, `scripts/uninstall.sh`, `systemctl`, or the daemon as root. Never restart `plasmashell`.
- Never install the widget into the real user Plasma directories. Only use `kpackagetool6 ... --packageroot <tempdir>`.
- Test parallelism stays low: `cargo test --offline -- --test-threads=2`.
- Existing `StatusData` fields and IPC requests are unchanged. Every new `StatusData` field is `#[serde(default)]`.
- The widget never talks to the socket directly. It only runs `/usr/local/bin/olly` (absolute path).
- Mood colours are fixed:
  - calm `#3ddc84`
  - watch `#4fc3f7`
  - worried `#ffb74d`
  - onit `#ff5252`
  - needs `#ffa726`
  - nap `#9575cd`
  - offline `#6b7378`
- The face screen is `#14171a`.
- All user-facing copy is in olly's cheery voice. Existing CLI text keeps its 🤖 prefix, and the widget strips a leading `🤖 ` before showing it.
- Status polling is every 2000 ms. "On it!" lingers 60 000 ms. Pause from the popup is 30 min (`olly pause 30`).

## Review Focus

1. **The daemon is stopped or restarting.** The face shows Offline with no error popups or log spam, and recovers on the next successful poll. Pinned by the `mood` offline tests (Task 3) and `json_offline_when_no_socket` / `json_offline_when_daemon_silent` (Task 2).
2. **An older daemon returns status without the new fields.** The widget still shows a mood from `level`, `paused_until_wall_ms` and `frozen`, and nothing throws. Pinned by `old_status_without_new_fields_parses` (Task 1) and `mood_old_daemon_shape` (Task 3).
3. **A frozen app is answered elsewhere** (through the notification) while the popup is open. Its card disappears on the next poll. Pressing a button for a gone id shows the CLI's error inline. Pinned by `needs_cards_follow_frozen_info` (Task 3). The inline error path is checked in Task 4, Step 6.
4. **Two apps are frozen at once.** There are two cards, and the face stays on Needs you until both are answered. Pinned by `mood_needs_until_all_answered` (Task 3).
5. **Long app names, and incidents with no actions or diagnosis.** Text is elided, and the dot and sub-line still render. Pinned by `incident_dot_and_sub_line_edge_cases` (Task 3).

### Task 2: `--json` output and offline timeout in the CLI

**Interfaces:**
- Consumes: `StatusData` (Task 1), `Request`.
- Produces:
  - `olly status --json` and `olly incidents [-n N] --json`. The flag may come before or after `-n N`.
  - On success, they print the daemon's `data` value as one compact JSON line and exit 0.
  - If the socket can't be reached, or no reply line arrives within 1000 ms, they print exactly `{"offline":true}` and exit 1.

### Task 3: Tray logic library and its tests

**Files:**
- Create: `plasmoid/package/contents/ui/logic.js`. The first line is `.pragma library`. It holds only pure functions, with no QML imports and no `Date.now()`; callers pass `now`.
- Create: `tests/tray/logic.test.mjs`. It loads `logic.js` with `fs`, drops the `.pragma library` line, and evaluates it with `new Function(src + "; return {mood, moodInfo, barColor, gb, relTime, countdown, incidentDot, incidentSummary, incidentSub, needsCards, stripBot, pausedNow};")()`. It uses `node:test` and `node:assert/strict`.
- Modify: `.github/workflows/ci.yml` to add `actions/setup-node@v4` (node 20) and `node --test tests/tray/` after `cargo test`.

**Interfaces:**
- Consumes: the JSON shapes from Task 1 and `docs/ipc.md`, and `{"offline":true}` from Task 2.
- Produces (used by Task 4's QML as `Logic.<fn>`):
  - `mood(status, now) -> "offline"|"needs"|"onit"|"nap"|"worried"|"watch"|"calm"`. `status` is a parsed object or `null`. The first match wins:
    1. `status == null || status.offline` → `offline`
    2. `(status.frozen_info||[]).length || (status.frozen||[]).length` → `needs`
    3. `status.last_action_wall_ms != null && ((status.incident_active && status.incident_acted) || now - status.last_action_wall_ms < 60000)` → `onit`
    4. `status.paused_until_wall_ms != null && status.paused_until_wall_ms > now` → `nap`
    5. `level` ∈ `warning|critical|emergency` → `worried`
    6. `level == "watch"` → `watch`
    7. otherwise → `calm`
  - `moodInfo(m) -> {name, color}`. The names are `All good!`, `Watching`, `Worried`, `On it!`, `Needs you!`, `Napping`, `Offline`, and the colours are the Global Constraints colours.
  - `barColor(kind, v) -> color`. `kind` is one of:
    - `"ram"`: `v` is the free fraction. Green when `> 0.20`, amber when `>= 0.10`, red otherwise.
    - `"swap"`: `v` is the used fraction. Green when `< 0.50`, amber when `<= 0.80`, red otherwise. A total of 0 is passed as 0.
    - `"psi"`: `v` is a percent. Green when `< 10`, amber when `<= 30`, red otherwise.

    Green, amber and red are the calm, worried and onit colours.
  - `gb(bytes) -> string`. This is the same rule as `voice::fmt_bytes`: `>= 9.95e9` → `"21 GB"`; `>= 0.95e9` → `"1.2 GB"`; else `"512 MB"`.
  - `relTime(ms, now) -> string`. The rules:
    - under 60 s → `"just now"`
    - under 1 h → `"Nm ago"`
    - under 24 h → `"Nh ago"`
    - under 48 h → `"yesterday"`
    - under 7 days → short weekday (`"Mon"`)
    - otherwise → `"Oct 3"`

    Use the local time zone through `Date` methods, and English names from a fixed array (no locale APIs, so tests are stable).
  - `countdown(killAtMs, now) -> "m:ss"`, clamped at `"0:00"`.
  - `incidentDot(inc) -> color`. It is the onit colour if any action is `Kill`, the needs colour if any is `Freeze`, and the worried colour otherwise. Actions are `[wall, {"Kill":{...}}, dry]`, so the action name is the first object key.
  - `incidentSummary(inc) -> string`: the incident's `summary`, or `"Something happened"` if it's empty.
  - `incidentSub(inc) -> string`. It is the first line of `diagnosis`, prefixed `Claude: `, cut at 70 chars with `…`. With no diagnosis it is `peak stall N%`, where `N = Math.round(peak_full)`. The spec said "peak level"; the incident record has no level, so this uses `peak_full`, which is the stored measure.
  - `needsCards(status, now) -> [{id, name, size, rateText, countdown}]` from `frozen_info`. `rateText` is `"it was growing X/min"` using `gb(rate*60)`, or `""` when `rate <= 0`. With an old daemon (no `frozen_info` but `frozen` present), it maps `frozen` with `rateText: ""` and `countdown: ""`.
  - `stripBot(text) -> string`: trims, and removes one leading `🤖` plus the whitespace after it.
  - `pausedNow(status, now) -> bool`.

- [ ] **Step 1: Write the failing tests** in `tests/tray/logic.test.mjs`. Each name is a `test(...)` title:
  - `mood precedence`: one fixture per rule. A status that matches several rules returns the earliest one (e.g. frozen + paused + warning → `needs`).
  - `mood offline`: both `null` and `{offline:true}` → `offline`.
  - `mood_old_daemon_shape`: today's `docs/ipc.md` StatusData example with `level:"warning"` → `worried`, and with `frozen:[{id:2,...}]` → `needs`.
  - `mood_needs_until_all_answered`: two `frozen_info` entries → `needs`; one → `needs`; none, with an action 30 s ago → `onit`.
  - `onit linger`: an action at `now-59999` → `onit`; at `now-60001` with no incident → by level.
  - `barColor thresholds`:
    - `ram`: 0.21 → green, 0.20 → amber, 0.10 → amber, 0.09 → red.
    - `swap`: 0.49 → green, 0.5 → amber, 0.8 → amber, 0.81 → red.
    - `psi`: 9.9 → green, 10 → amber, 30 → amber, 30.1 → red.
  - `gb matches fmt_bytes`: the four cases from `voice::fmt_bytes_cases`.
  - `relTime`: each bucket boundary, using fixed `now` dates.
  - `countdown`: 252 000 ms → `"4:12"`; a past deadline → `"0:00"`.
  - `incident_dot_and_sub_line_edge_cases`:
    - a Kill → red; a Freeze only → orange; a Throttle only → amber.
    - No actions → amber, and the sub-line is `peak stall 0%` when `peak_full` is 0.
    - A long multi-line diagnosis is cut to one line ending `…`.
  - `needs_cards_follow_frozen_info`: cards match `frozen_info` ids in order, and an empty `frozen_info` gives `[]`.
  - `stripBot`: `"🤖 olly isn't running"` → `"olly isn't running"`; text without the emoji is unchanged.
